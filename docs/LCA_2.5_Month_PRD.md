# **1. Purpose & Scope**

This PRD extracts and sequences six initiatives from the LCA Enterprise Architecture Data Sheet into a 2.5-month delivery plan. Only the items below are in scope for this document; the remaining architecture (full CRM agent suite, payment-gateway abstraction, multilingual voice search, complete android app, and the other 20+ AI agent roles) stays on the longer-term roadmap described in the source document and is not scheduled here.

**In-scope initiatives**

- Platform migration — complete migration of backend, frontend and database from the existing ASPX site to .NET (ASP.NET Core / .NET 10, React + Next.js + TypeScript), including migration of existing business logic, authentication, product/catalogue, customer, pricing, inventory, cart, order and RFQ flows, while keeping the existing site operational during the transition.

- Android application foundation — develop the Android customer application in Flutter, integrated with the same secured backend APIs used by the web application.

- Shared API layer — establish secured and versioned APIs for Web and Android, with common authentication, authorization, validation, pagination, filtering and error-handling conventions.

- AI Media Agent — generates product images and video from product specifications, raw images and a user prompt, and places them in the same slots already used on the live site.

- AI Marketing Agent — drafts and posts ads/campaigns to LinkedIn and other configured channels.

- AI Analytics Chatbot — plain-English chat interface that answers product/business questions with supporting charts and graphs, sourced from the live database.

- Product Onboarding Automation — replaces the current manual process of adding products, specs and images with a chatbot-driven pipeline.

- AI Logistics Agent — compares shipping paths, carriers and pricing, and recommends the best option for each shipment.

- Governance constraint (applies to all of the above): the owner holds the final decision on every action — see Section 2.

# **2. Governing Principle — Owner Has the Final Decision**

This is a cross-cutting requirement, not a separate feature: none of the four agents (Media, Marketing, Analytics Chatbot, Logistics) or the automation pipeline is permitted to take an external or live action on its own. Every agent produces a draft, a recommendation, or an analysis; the owner approves or rejects it.

- Deny-by-default permissions: each agent only gets the specific data/tool access it needs, enforced by an Agent Permission Engine.

- Products, specifications and media generated by AI are saved as drafts pending human approval before they go live.

- Marketing posts are queued for the owner's authorization before anything publishes externally.

- The Logistics Agent recommends a carrier/path/price; the owner books it.

- AI cannot invent or directly overwrite price, stock, SKU or order status, and cannot authorize refunds or high-value actions.

- Every agent action is logged end-to-end: user, agent, tool used, data touched and the approval decision.

# **6. Cross-Cutting Constraints**

- AI never writes price, stock or SKU directly — product/specification edits are draft-only pending human approval.

- Generated media (image/video) is kept in a separate draft pool from original product photography until approved.

- Every external integration (LinkedIn, courier/3PL providers) requires credentials/OAuth, a health check, a retry policy and an audit trail.

- No customer-facing client (web/app) connects to the production database directly — all access goes through the shared, secured APIs.

- Customer-specific price and inventory visibility remains enforced server-side throughout the migration.

# **7. Go-Live Acceptance Checklist**

- Existing ASPX site data has been mapped and reconciled against the new database.

- New frontend and any other channel use the same secured APIs — no duplicate product/customer/order data stores.

- Analytics chatbot answers reflect only authorized, real data — spot-checked against the database.

- Generated media is visually distinguishable/tagged as AI-generated until the owner approves it for publication.

- LinkedIn (and other) marketing OAuth flow and posting permissions tested end-to-end.

- Logistics Agent recommendations tested against every configured carrier/provider.

- Audit log captures every AI-initiated action with user, agent, tool and approval outcome.

- Owner approval is required and enforced before: a product goes live, generated media goes live, a marketing post publishes, or a shipment is booked.

# **8. Assumptions, Dependencies & Risks**

- Timeline assumes kickoff on Monday, 17 August 2026; shift all sprint and deliverable dates by the same offset if the real start date differs.

- “Complete” migration of backend, frontend and database in the first 8 weeks (Sprints 1–4) while simultaneously standing up four new AI agents is an aggressive scope; running a dedicated migration squad in parallel with a separate AI-agent squad is recommended over one team doing both sequentially.

- Assumes the existing ASPX database schema and data exports are accessible for mapping in Sprint 1.

- Assumes LinkedIn (and any other ad platform) developer/business accounts and API access are approved and available before Sprint 5.

- Video generation (Sprint 5) is the highest-risk item — its timeline depends on the chosen AI provider's video capability, quality and cost; a fallback (images-only launch, video slipping to a follow-on phase) should be agreed in advance.

- Everything outside the six initiatives above — the full CRM agent suite, payment-gateway abstraction, multilingual/voice search, the Android app, and the remaining AI agent roles — is intentionally excluded from this 2.5-month PRD and remains on the longer-term roadmap.
